**Author:** Sergio Farfan
**Date:** 2026-09-19
**Plugin:** oci-drawio-architect 1.4.0 -> 1.5.0
**Repository:** `OCI-draw.io-Architect` (public, MIT), branch `feature/v1.5.0-view-and-detail-controls`
**Extends:** `docs/superpowers/specs/2026-09-17-topology-aware-placement-design.md` (v1.3.0),
`docs/superpowers/specs/2026-09-17-security-constructs-addendum.md` and
`docs/superpowers/specs/2026-09-18-v1.4.0-placement-enrichments-design.md` (v1.4.0). Model schema 2,

## 1. Goal and scope

v1.3.0 made placement topology-aware; v1.4.0 fixed *where things go*. v1.5.0 answers the remaining
question: **what goes in, and how much of it**. One discovered topology, several readable views.

- **Label modes.** Captions stop being a fixed hand-written template and become a rendered field
  list: Minimal, **Network (the new default)** and Detailed, over a documented field vocabulary
  (display name, type, private / public IP, CIDR, FQDN, port / protocol, compartment, AD / FD,
  lifecycle, tags; OCID never in a caption).
- **View layers.** The diagram is emitted onto real draw.io layers so route, security, IAM,
  data-flow and management content can be toggled in the application without regenerating.
- **Detail levels.** Executive / application / network / engineering, each a named composition of
  layers, label mode and a small table of content gates.
- **Filtering.** One shared predicate over tags, compartment, region, VCN, subnet, resource type,
  environment and application/team, applied identically by the Terraform parser, the live-tenancy
  reader and the layout CLI.
- **Participating mode.** "Every discovered resource" or "only the resources that take part in the
  architecture".
- **Relationship-discovery provenance.** `edges[].discovery` replaces the `inferred` boolean and
  becomes a filter axis.
- **A global-services bucket.** IAM, Policies, Audit, Public DNS and the compartment list in a
  tenancy-scoped box distinct from the regional Oracle Services Network.
- **Purpose presets.** The six purposes the team's diagram guidelines name, each a composition of
  everything above, asked once in the command's Step 1.

Non-goals (section 13): AD / FD containers, multi-region canvases, security-rule reachability
analysis, observed-traffic discovery, a portrait canvas, per-view PDF/PNG batches. Everything stays
standard-library Python 3.9+, schema 2, deterministic (`key=` ids), gated by `check_overlaps.py`.

Backlog coverage: C01-C08 of the post-release triage, in its build order - **C05** (layers) and
**C04** (label modes) first because they are layout-local and the builder primitive already exists
unused, then **C03** (detail levels), then **C02** (filtering) with **C07** (participating) riding on
its pruning machinery, **C08** (discovery provenance) in parallel, **C06** (global bucket) once the
tenancy-container question is settled, and **C01** (purposes) last as the composition of the others.

## 4. Design decisions (fixed)

**D1-D3** were taken by the author on 2026-09-19 and are not reopened. **V1-V10** are the
consequences this specification settles. **A1-A5** are the five choices that were the author's;
they were answered on 2026-09-19 and are recorded, with their rationale, in section 14.

- **D1. Label modes ship with `network` as the default.** Minimal / Network / Detailed follow the
  team's guidelines section 7 table; the default caption is name + private IP + port / protocol. The
  field list is configurable through the model (`label_fields`), with the mode as a preset.
  `MAX_LABEL_LINES` becomes mode-aware. This changes shipped output and shipped screenshots (11).
- **D2. Build order** is the triage's: C05 and C04, then C03, then C02 with C07, C08 in parallel,
  C06, and C01 last.
- **D3. No new runtime dependency, no schema bump.** Standard-library Python 3.9+, schema 2,
  additive optional fields only (justified in 5), deterministic ids, the existing gates.

- **V1. A layer is a post-pass, not a layout change.** The recipe lays out exactly as it does today;
  a final pass creates the layers and moves the layer-eligible cells onto them with
  `reparent()`, which preserves absolute position. Enabling layers therefore cannot move a pixel,
  and the geometry tests are unaffected.
- **V2. Only cells that are not nested inside a drawn container can be layered.** In draw.io a
  layer is a child of the root and a cell belongs to the layer of its top-level ancestor, so hiding
  a layer hides whole subtrees. A workload icon inside a subnet cannot be toggled independently of
  its subnet. Every layer name in the guidelines' section 8 therefore resolves to exactly one of
  three mechanisms - **cell layer**, **label field**, **build-time selector** - and 6.2's table
  states which, for all twelve.
- **V3. Layers are opt-in in 1.5.0** (`layers: "off"` by default). With them off the output is
  byte-identical to 1.4.0 for the same model apart from D1's caption change.
- **V4. A view that excludes content hides its layer when layers are on, and drops the cells when
  they are off.** That is the whole value of the feature: with `--layers auto --purpose dataflow`
  the route and security badges are present but hidden, and the reader can switch them back on in
  draw.io without regenerating.
- **V5. The caption renderer never discards an authored caption.** The rendered caption is the
  item's own `label` (which may already be multi-line and is kept verbatim) followed by the mode's
  extra fields, each skipped when its value already appears in the label text - the same
  "do not repeat what is already there" rule `oci_topology.label_parts` uses for the public /
  private token. A hand-written model therefore renders as it does today in every mode.
- **V6. Detailed captions grow the caption box, not the slot width.** `label_h` and the icon row
  pitch become mode-aware; `ICON_W`, `LABEL_W` and `COL_W` do not change, so the subnet grid, the
  `MAX_ROW_W = 1000` row budget and every container width formula are untouched. Because rule 5
  already passes any caption whose box is tall enough (`e["h"] >= n * fs * 1.25`), the file-level
  gate stays correct without knowing the mode.
- **V7. Oracle and the team's guidelines disagree about IAM, and the guidelines win as an option,
  not as the default.** Slides 29-31 draw IAM / Auditing / Policies inside the Oracle Services
  Network box; the guidelines' section 4 wants a separate global bucket. 1.5.0 implements the
  bucket (`global_services: "bucket"`), keeps `"osn"` as the default so that D1 is the release's
  only default flip, and turns the bucket on automatically under the `security` and `inventory`
  purposes. (Author decision **A2**, 14.)
- **V8. `discovery` is metadata and a filter axis, never a connector style.** The guidelines'
  section 2 already binds the four line styles to four meanings; a second visual axis over the same
  lines would make the notation ambiguous, which is the specific failure that section warns about.
- **V9. Filtering is one pure function over the model, in one new stdlib module.** Both front ends
  and the layout CLI call it, exactly as `oci_topology.py` already lets `parse_terraform.py`
  validate model shapes without importing the builder.
- **V10. Validation stays layer-blind and validates everything.** No rule reads `visible` today and
  none will: a hidden layer must still be clean when it is shown. This is safe because all
  containers stay on the base layer (V2), so no overlap rule can fire between cells that are never
  displayed together.

## 5. Model schema delta

`schema_version` **stays 2**. Every key below is optional and additive; no existing key changes
meaning or type. Three compatibility points justify not bumping to 3:

1. `edges[].inferred` keeps being written, derived from `discovery` (6.8), so an existing consumer
   that reads it is unaffected.
2. `subnet_label` gains a third value `"name"`. This is an enum **widening**: every 1.4.0 value
   stays valid and only a 1.5.0 writer emits the new one. `oci_topology._choice` rejects unknown
   values, so an old reader fails loudly rather than silently mis-rendering.
3. Item `metadata` keeps its scalar-only contract (`ModelBuilder._item_for` filters to
   `str | int | float | bool`); tags therefore go in a **new sibling key** `item["tags"]`, not in
   `metadata`.

## 6. Design

### 6.1 One view context, one resolution order

All view state is resolved once, by a new pure module **`scripts/oci_view.py`** (standard library
only, imports nothing from the plugin), mirroring the role `oci_topology.py` plays for topology:

```python
PURPOSES, DETAIL_LEVELS, LABEL_MODES, LABEL_FIELDS, VIEW_LAYERS   # the preset tables of 6.2-6.9
resolve_view(model, **overrides) -> dict     # the whole view, every key concrete
render_caption(item, view, kind="icon") -> str
filter_model(model, spec) -> dict            # 6.5, returns a new model + a report
participating(model) -> set                  # 6.6
```

Resolution order, most specific first: **explicit CLI flag -> `build_diagram` kwarg -> explicit
model key -> `detail` preset -> `purpose` preset -> hard default.** This is the v1.4.0 rule
(`_view_ctx`, where the kwarg wins over the model key) with two preset levels inserted below the
model. `_view_ctx` keeps its name and signature style, gains the new kwargs, and delegates to
`resolve_view`; the resolved dict is stored in `layout_info["view"]`, so every diagram records the
view that produced it.

A `_choice()`-style reader in `oci_view.py` validates every enum and raises `ValueError` on an
unknown value, as `oci_topology._choice` does today.

### 6.2 View layers (C05)

**The constraint.** A draw.io layer is a child of the root (`add_layer` emits `parent="0"`), and a
cell belongs to the layer of its top-level ancestor. Hiding a layer hides the whole subtree beneath
it. An icon inside a subnet, a subnet inside a VCN and a VCN inside the region are therefore all on
the region's layer, whatever we would like. Emitting the IP or the port as a *separate text cell* -
the mechanism the guidelines' touch points suggest - does not help: that cell would also be a child
of the subnet, and would additionally have to be kept clear of the caption box to satisfy rule 4.
This is why V2 splits the twelve requested layers across three mechanisms.

| Guideline layer | Mechanism | What it is in 1.5.0 | Default |
|---|---|---|---|
| Network | **base layer** | Cell `"1"`, renamed `Network`: the region, the location boxes, every container, every icon inside one, gateways, the DRG cluster and attachment boxes, attachment connectors, the title, notes and legend | visible (draw.io allows hiding it; the command warns that this blanks the page) |
| Application resources | build-time | Workload icons are children of their subnet (V2). Governed by `detail`, `filter` and `mode` | - |
| Routes | **cell layer** `routes` | Subnet route-table badges (`<subnet>-rt`) and DRG route-table badges (`<drg>-rt`, `-rt2`) | visible |
| Security | **cell layer** `security` | Security-list badges (`<subnet>-sl`) and NSG badges (`<icon>-nsg`). WAF, bastion and firewall **icons** are subnet children, so they stay build-time (the `security` purpose keeps them, the `executive` detail drops them) | visible |
| IAM | **cell layer** `iam` | The global-services bucket of 6.7 and its icons - page-level, therefore layerable. With `global_services: "osn"` the IAM icons are children of the OSN panel and the layer is not created | visible |
| Observability | build-time | Logging / Monitoring / Notifications icons are children of the OSN panel | - |
| Data flows | **cell layer** `dataflow` | Edges of kind `data`, `analytics`, `datalake` (their labels travel with the edge cell) | visible |
| Management paths | **cell layer** `management` | Edges of kind `control` | visible |
| (added) Associations | **cell layer** `associations` | Edges of kind `association`. `attachment` edges stay on the base layer: they are structure, not annotation | visible |
| Compartments | build-time | A compartment container **holds** the VCNs, so it cannot be on another layer. `show_compartments` (v1.4.0) is the toggle | off |
| AD / FD | out of scope | No AD / FD containers exist (13) | - |
| Resource IPs | **label field** | `private_ip` / `public_ip` in `label_fields`. `--layers ips` is accepted and rewritten to that field, with a note on stderr | per label mode |
| Ports and protocols | **label field** | `port_protocol` in `label_fields`, plus the connector labels, which live on the edge's own layer | per label mode |

**Implementation (V1).** After `fit_page()` in `build_diagram`, when layers are enabled:

1. `d.set_base_layer_name("Network")` - a new one-line builder method that sets `value` on the
   page's `"1"` cell (today it is emitted without one, so draw.io shows an unnamed background
   layer).
2. For each enabled layer, in the fixed order `routes, security, iam, dataflow, management,
   associations`: `lid = d.add_layer(<Title Case name>, visible=name not in hidden, key=f"layer-{name}")`.
   The order is the z-order; all of them render above the base layer, which is what badges and
   connectors need.
3. Move the cells: badges with `d.reparent(bid, lid)` (absolute position preserved); edges by
   passing `parent=lid` at `add_edge` time, since an edge's route is computed from absolute boxes in
   `_routing_shapes` and the parent only selects the coordinate frame the waypoints are stored in.
4. A layer that would be empty is not created.

**Validator (V10, 7).** One new rule-7 exemption is required and is the only validator change: a
badge moved onto a layer is no longer a descendant of the subnet or icon it decorates, so
"lies inside ... but is not one of its children" would fire. Rule 7 gains: *a leaf whose
`ociHost` (style token, read by `_badge_host`) names a cell that is the container itself or a
descendant of it is not foreign*. Rule 3 needs nothing - it already skips a vertex whose parent's
kind is not `group`, and a layer's kind is `layer`. Rule 2 cannot fire across layers because every
container stays on the base layer. `validate_file` and `check_overlaps.py` continue to validate
every cell on every layer regardless of `visible`.

**draw.io behaviour to document** (`SKILL.md`, `gotchas.md`, command Step 6): layers are edited
through *Extras > Edit Diagram* or the layers panel (`Ctrl+Shift+L` / `Cmd+Shift+L`); a hidden layer
is `visible="0"` in the XML and stays hidden when the file is reopened; hiding the base `Network`
layer blanks the drawing; a PNG / PDF export renders only the visible layers, which is the intended
way to produce a filtered image from one file.

**Surface.** Model `layers` and `hidden_layers` (5); CLI `--layers off|auto|<csv>` and
`--hidden-layers <csv>`; `build_diagram(layers=, hidden_layers=)`;
`layout_info["layers"] = {"enabled": [...], "hidden": [...], "cells": {name: n}}`.

### 6.3 Label modes (C04, D1)

**Field vocabulary** (the guidelines' section 7 list, with the model source of each):

| Field | Renders as | Source |
|---|---|---|
| `display_name` | line 1, the item's authored `label` verbatim (V5) | `item["label"]` |
| `resource_type` | `Compute instance` - the human default from `RESOURCE_ICONS[type][1]` | `item["type"]` |
| `private_ip` | `10.0.2.47` | `metadata.private_ip`, else `metadata.ip_address` |
| `public_ip` | `203.0.113.10` | `metadata.public_ip` |
| `cidr` | `10.0.2.0/24` | containers only (subnet / VCN title) |
| `fqdn` | `broker.sub01...` (elided to the caption width) | `metadata.fqdn` |
| `port_protocol` | `TCP/22, 8088` | `metadata.ports` |
| `compartment` | `Compartment: app-prod` | `metadata.compartment` |
| `ad_fd` | `AD-1 / FD-2` - the AD name is reduced to its trailing `AD-n`, the fault domain to `FD-n` | `metadata.availability_domain`, `metadata.fault_domain` |
| `lifecycle` | `AVAILABLE` (rendered only when it is not the healthy state) | `metadata.lifecycle_state` |
| `tags` | `Environment=prod` for each key in `label_tag_keys`, in that order | `item["tags"]` |
| `ocid` | **never rendered in a caption, in any mode.** It is in the tooltip and metadata | `item["address"]` under `query_tenancy` |

**Modes.**

| Mode | `label_fields` | Line budget | Caption box |
|---|---|---|---|
| `minimal` | `[display_name]` | 2 | `LABEL_H = 45` |
| `network` (default) | `[display_name, private_ip, port_protocol]` | 3 | `LABEL_H = 45` |
| `detailed` | `[display_name, private_ip, ad_fd, compartment]` | 5 | `LABEL_H_DETAILED = 76` |

`label_fields` overrides the preset; an unknown field name is a `ValueError`. Fields whose value is
missing are skipped silently - a caption never contains an empty line or a placeholder. A field
whose value already occurs in the text rendered so far is skipped (V5), which is what keeps
`"Load Balancer\n10.0.0.23"` from becoming `"Load Balancer / 10.0.0.23 / 10.0.0.23"`.

**Per element.**

- **Icons** (workloads, services, hub items): the table above.
- **Subnet titles**: `minimal` -> name plus the `(Public)` / `(Private)` token, no CIDR (a new
  `subnet_label` value `"name"`); `network` and `detailed` -> the v1.4.0 two-line form
  (`_subnet_title_lines`, `label_parts`). This is how the guidelines' "show subnet CIDRs when the
  view is network-focused" becomes mechanical.
- **VCN titles**: the same rule, over `_vcn_title_lines`.
- **Gateways**: the authored two-line caption in every mode; `detailed` appends `resource_type`
  when the caption does not already name it. Gateway captions are width-critical (they straddle a
  border and carry `label_fill`), so no other field is added.
- **Attachment boxes**: unchanged in every mode (`_att_box_text` already grows the box to its text).
- **Badges**: never gain a caption - that is the whole point of the security-constructs addendum.
  The mode reaches them only through the tooltip: `detailed` renders
  `Route table: rt-app (oci_core_route_table.app)` where `network` renders `Route table: rt-app`
  (`oci_layout._badge_tooltip`).
- **Edge labels**: `minimal` drops them, `network` and `detailed` keep them. `detail: "executive"`
  drops them independently (6.4).

**Geometry (V6).** New constants in `drawio_builder.py`: `LABEL_H_DETAILED = 76` and
`LABEL_LINE_BUDGET = {"minimal": 2, "network": 3, "detailed": 5}`. `ICON_FOOTPRINT_H` keeps its
value and is joined by `icon_footprint_h(label_h)`; `oci_layout._icon_items` passes
`row_h=ROW_H + max(0, label_h - LABEL_H)` and `label_h=` through `place_icons`, both of which
already accept them. 5 lines at `LABEL_FONT_SIZE = 11` need `5 * 11 * 1.25 = 68.75 px`, so a 76 px
box satisfies rule 5's height escape and the written file validates under the default
`max_label_lines = 3` - the CLI gate needs no mode knowledge. For the in-memory path
`DrawioBuilder(max_label_lines=...)` is added and threaded into `validate()`'s call to
`validate_registry` (which already takes the parameter and is never given it), so a builder-level
warning matches the mode.

**Parser change.** `ModelBuilder._item_for` stops appending the shape line; `shape` is already in
`METADATA_KEYS`, so the value is not lost and `detailed` can render it as part of
`resource_type`. This is the visible default change of 11.

### 6.4 Detail levels (C03)

A detail level is a row of gates plus defaults for the finer keys. `DETAIL_LEVELS` in
`oci_view.py`:

| Gate | `executive` | `application` | `network` (default) | `engineering` |
|---|---|---|---|---|
| `label_mode` | `minimal` | `minimal` + `port_protocol` | `network` | `detailed` |
| `subnet_cidr` (subnet / VCN titles) | no | no | yes | yes |
| `badges_routes` | no | no | yes | yes |
| `badges_security` (SL, NSG) | no | no | yes | yes |
| `drg_route_table` | no | no | no | yes |
| `drg_attachments` (boxes) | no | yes | yes | yes |
| `gateways` | yes | yes | yes | yes |
| `edge_labels` | no | yes | yes | yes |
| `osn` | yes | yes | yes | yes |
| `legend` | yes | yes | caller's choice | yes |
| `layers` default when `layers: "auto"` | `dataflow` | `dataflow, management` | all | all |

Every gate is also an explicit model key of its own only where one already exists
(`show_compartments`, `subnet_label`, `legend`); the rest are internal to the resolved view and are
reachable through `detail` or `purpose`. A gate that removes content **hides the corresponding
layer instead of dropping the cells whenever layers are enabled** (V4): with
`--detail application --layers auto`, the route and security badges are emitted and hidden.

`executive` is the only level that changes structure rather than decoration: no badges, no DRG route
table, no attachment boxes (the DRG connects straight to the VCN border, which is the
`vcn_with_drg` presentation the classifier already knows), no CIDRs, no connector labels.

### 6.5 Filtering (C02)

**Expression grammar** (one string per expression, so it survives a CLI, a JSON model and a settings
file unchanged):

```
[!]<dimension>[:<key>]<op><value>[,<value>...]
op  :=  '='   exact, case-insensitive
    |  '~'   substring, case-insensitive
```

| Dimension | Matches against |
|---|---|
| `tag:<key>` | freeform **or** defined tag `<key>` (a defined tag key is `<namespace>.<key>`) |
| `ftag:<key>` / `dtag:<ns>.<key>` | the one namespace explicitly |
| `compartment` | `metadata.compartment`, else the owning VCN's `compartment` |
| `region` | `model["region"]` (a whole-model predicate; it either keeps or empties the model) |
| `vcn` / `subnet` | the owning container's name or address |
| `type` | the Terraform / entity type (`item["type"]`) |
| `icon` | the icon key |
| `name` | the first line of the caption |
| `address` | the model address (an OCID under `query_tenancy`) |
| `env` | `tag:Environment`, `tag:environment`, `tag:env` - the first one present |
| `app` | `tag:Application`, `tag:application`, `tag:app`, `tag:Team`, `tag:team` |

`env` and `app` are conventions, not OCI concepts; they are documented as sugar over `tag:` and the
key list is a module constant so a project can see exactly what is tried.

**Semantics.** Expressions in `include` are ANDed **across dimensions** and ORed **within a
dimension** (two `vcn=` expressions mean either VCN, which is what a user means). `exclude` always
wins. An empty `include` means everything is in scope. Multiple `--filter` flags accumulate into
`include`; a leading `!` puts the expression into `exclude`.

**What the predicate applies to, and what survives it.**

- Predicated: items in subnets, VCN-level services and controls, top-level services, hub / internet /
  third-party items.
- **Structure is not predicated**: gateways, DRGs, attachments, subnets and VCNs survive unless a
  `vcn=`, `subnet=`, `type=` or `name=` expression names them directly. A subnet emptied by the
  filter is dropped; a VCN with no subnets, no gateways and no services is dropped; `keep_empty:
  true` in the filter spec keeps them as empty containers.
- **Edges**: an edge whose endpoint disappeared is dropped - the precedent is `select_vcn`, which
  does exactly this. No stub or ghost node is drawn (13). The count is reported, so the diagram can
  say what was elided.
- **DRG attachments** to dropped VCNs are pruned and dangling LPG `peer` values are nulled, by the
  helper `_prune_dangling(model)` extracted from `select_vcn` and shared with it.

**Surfaces.** `parse_terraform.py` and `query_tenancy.py` gain `--filter EXPR` (repeatable),
`--tag K=V`, `--compartment NAME`, `--subnet NAME`, `--resource-type TYPE` (the last four are sugar
that build `include` expressions). `oci_layout.py` gains `--filter EXPR` (repeatable) applied before
layout, so a saved model can be re-cut without re-parsing. `--vcn` / `--vcn-id` keep their exact
current behaviour, are documented as the single-VCN shortcut (they also rewrite `subject`), and are
reimplemented on top of the shared `_prune_dangling`.

In `query_tenancy.py`, `--tag` and `--resource-type` may additionally narrow the
`oci search resource structured-search` query text server-side. That is an optimisation: the
implementation task must verify the tag predicate syntax against the OCI Search documentation, and
the client-side `filter_model` pass runs unconditionally afterwards, so correctness never depends on
it.

**Tag retention (the real parser cost).** `freeform_tags` and `defined_tags` leave `_SKIP_ATTR_KEYS`
and are read in both ingestion paths - the HCL collector must accept a map-valued attribute
(`freeform_tags = { "Application" = "payments" }`) and the JSON flattener must keep the nested
object rather than dropping it. A tag whose value is an unresolved expression (a `var.`/`local.`
reference the parser cannot evaluate) is skipped with a `WARNING` in `model["warnings"]`, because a
filter that silently matches nothing is worse than one that says why.

**Reporting.** `layout_info["filter"] = {"include": [...], "exclude": [...], "items_kept": n,
"items_dropped": n, "edges_dropped": n, "containers_dropped": n}`, echoed by `summarise()` in both
front ends and by the command's Step 6.

### 6.6 All-resources versus participating mode (C07)

`mode: "all" | "participating"`. An item **participates** when any of these holds:

1. it is an endpoint of an edge that survives filtering;
2. it is structure - a gateway, a DRG, a DRG attachment, a hub / internet / third-party item;
3. it carries a badge (`nsgs`) or is a badge host;
4. it is named by a `groups[]` box;
5. it is named directly by an `include` filter expression (an explicit request always wins);
6. it is the only item of its subnet **and** the subnet is kept for structural reasons - so a
   deliberately drawn empty-ish tier does not silently vanish.

Everything else is pruned, with `layout_info["pruned"] = {"items": n, "services": n}`. The dominant
case is a regional service with no edge: a tenancy dump routinely produces dozens, and they are the
main reason a live-tenancy diagram is unreadable.

Implemented as `oci_view.participating(model) -> set(addresses)` and applied by
`filter_model(..., mode=...)`, so filtering and pruning share one pass and one report. The default
is per front end: `all` for `parse_terraform.py`, `participating` for `query_tenancy.py`
(author decision **A1**, 14).

### 6.7 Global-services bucket (C06)

**Classification.** `oci_topology` gains a third class beside `is_regional`:

```python
GLOBAL_ICON_KEYS = frozenset({"iam", "identity", "policies", "policy",
                              "auditing", "audit", "dns"})     # public DNS zones
def is_global(item) -> bool     # item["scope"] == "global" wins; then the icon table
```

These seven keys are **carved out of** `REGIONAL_ICON_KEYS` rather than added to it: an item is
global, else regional, else VCN-resident. `services[].scope` (`global` | `regional` | `vcn`) is the
explicit override, and it wins over both tables - a private DNS resolver stays VCN-resident exactly
as `_VCN_RESIDENT_TYPES` already ensures for `oci_dns_resolver`.

**Placement.** With `global_services: "bucket"` the recipe emits one container of `group_type`
`tenancy` (already in `GROUP_TYPES`), key **`global`** - not `tenancy`, which `_layout_compartments`
already uses for the v1.4.0 compartment wrapper - labelled `Global services` or
`Global services (Tenancy: <name>)` when `tenancy_name` is set. It is a **page-level sibling of the
region in both canvases**, placed below the region and left-aligned with it, with
`GLOBAL_BAND_GAP = 45`. Page level is not a convenience: tenancy scope is above region scope, it
keeps the box out of every containment rule, and it is what makes the `iam` layer possible (V2).
The box holds one icon per global service and, when `show_compartments` is off and
`model["compartments"]` is non-empty, one `add_text` cell listing up to 12 compartment names with
`+N more` - the guidelines list Compartments among the global items, and they have no icon.

With the default `global_services: "osn"` nothing changes: the seven keys stay in
`REGIONAL_ICON_KEYS`'s behaviour through `is_regional` and land in the Oracle Services Network panel
or band, as Oracle's slides 29-31 draw them.

No connector is drawn to the bucket: a global service is not reached through the Service Gateway,
and inventing an edge would contradict the guidelines' section 5 path
`VCN -> Service Gateway -> Oracle Services Network -> Oracle service`.

### 6.8 Relationship-discovery provenance (C08)

`new_edge(source, target, label="", kind="data", discovery="association")` replaces the `inferred`
parameter and writes both keys: `inferred = discovery in ("reachability", "tag", "observed")`, so
every existing consumer of the boolean keeps working (5).

| `discovery` | Meaning | 1.5.0 producer |
|---|---|---|
| `association` | An explicit association declared in the source of truth | Load-balancer backend -> target, LPG pair, DRG attachments (`_build_edges`) |
| `config` | One resource's configuration references another | **New**: any resolved `*_id` reference between two drawn items (`Res.refs`) that is not already an association - a compute referencing a vault key, a function referencing a bucket. Emitted as `kind="association"` (dotted, no arrowhead), which is exactly what the guidelines' section 2 prescribes for a non-traffic relationship |
| `reachability` | Derived from routing | `query_tenancy._route_edges` (`ROUTES_TO`), today mislabelled `inferred=False`; it becomes `discovery="reachability"` |
| `tag` | Same application / team tag | **Not inferred in 1.5.0.** Tags are a filter and grouping dimension here; turning shared tags into edges produces a dense, low-information graph that fights the guidelines' readability target. Accepted from a sidecar or a hand-written model |
| `observed` | Observed traffic | Out of scope - there is no telemetry source in the plugin (13) |
| `user` | Declared by the operator | **New**: `--relationships FILE`, a JSON sidecar `[{"source", "target", "label", "kind"}]` merged into `edges[]` with `discovery: "user"` |

The heuristic edges of `_heuristic_edges` (load balancer -> app-tier compute; compute -> same-VCN
database with a `DB_PORTS` port) are **not** any of the six: they are a plausibility guess. They get
`discovery: "config"` only when they rest on a resolved reference, and otherwise a seventh value
**`heuristic`**, which is what `--no-inferred-edges` has always been about. The enum in the schema
is therefore the six from the guidelines plus `heuristic`, documented as the plugin's own.

**Selectors.** `--discovery association,config,user` (repeatable / comma-separated) on both front
ends and on `oci_layout.py`; `--no-inferred-edges` is kept as a documented alias for
`--discovery association,config,reachability,user`. A filter expression `discovery=heuristic` works
too, through the same predicate machinery.

**No style change (V8).** `discovery` never selects a connector style. `--annotate-discovery` puts
it in the edge tooltip, and `layout_info["edges"] = {discovery: count}` reports the mix.

### 6.9 Purpose presets (C01)

A purpose is a named composition. `PURPOSES` in `oci_view.py`:

| `purpose` | `detail` | label | layers (visible / hidden) | filter default | `mode` | other |
|---|---|---|---|---|---|---|
| `network` | `network` | `network` | routes, security, dataflow, management / - | none | `all` | today's look |
| `dataflow` | `application` | `[display_name, port_protocol]` | dataflow, management / routes, security | none | `participating` | edge labels on |
| `security` | `network` | `[display_name, private_ip]` | security, routes, iam, management / dataflow | none | `all` | `global_services: "bucket"`, `legend: true` |
| `inventory` | `executive` | `[display_name, resource_type, compartment]` | iam / - | none | `all` | `show_edges: false`, `show_compartments: true` |
| `dependency` | `application` | `[display_name]` | dataflow, management, associations / routes, security | none | `participating` | `--annotate-discovery` on |
| `ha` | `network` | `[display_name, ad_fd]` | routes / security | none | `all` | AD / FD as caption fields; AD / FD **containers** are out of scope (13) |

No purpose sets a filter: a filter is about *this* tenancy, a purpose is about *this* diagram. The
purpose only ever sets defaults - any explicit key wins (6.1).

**Surfaces.** `--purpose` on `oci_layout.py`; `purpose` in the model; `build_diagram(purpose=)`; and
a new question in the command's Step 1, asked with `AskUserQuestion` using the six names **verbatim
from the guidelines** ("Network topology", "Application / data flow", "Security architecture",
"Resource / inventory view", "Dependency / relationship view", "Deployment / high-availability
architecture"). Unlike the five v1.4.0 view keys, the answer **is** persisted, as `purpose:` in
`.claude/oci-drawio-architect.local.md`, because the guidelines ask for the purpose to be recorded;
Step 0 keeps the rule that a view choice is never *detected*, only answered and remembered
(author decision **A4**, 14).

For the generating agent, each purpose is documented in `SKILL.md` as a table row giving the exact
resolved view - the same table as above - plus one sentence on when to pick it, so the agent can
either pass `--purpose` or set the individual keys and get the identical result.

## 7. Builder changes (`scripts/drawio_builder.py`)

Small and mostly additive; none of them changes existing output.

1. `set_base_layer_name(name)` - set `value` on the page's `"1"` cell (6.2 step 1).
2. `add_layer` unchanged. `page["layers"]` finally has a reader: `layer_ids()` returns the current
   page's layers, used by the tests and by `layout_info`.
3. `DrawioBuilder(..., max_label_lines=MAX_LABEL_LINES)` stored on the instance and passed to
   `validate_registry` in `validate()` (the parameter exists and is never supplied today).
4. `LABEL_H_DETAILED = 76`, `LABEL_LINE_BUDGET`, `icon_footprint_h(label_h)`; `add_icon` already
   accepts `label_h=`, `place_icons` already accepts `row_h=` and forwards `**icon_kwargs`.
5. `style_extra=` on `add_icon` and `add_badge`, which alone among the `add_*` methods build their
   style as a fixed f-string. Not needed by this release's layer design (layers are a parent, not a
   token), but it removes the only cell kinds that cannot carry a future `oci*` token, and it is
   four lines through the existing `_merge_style`.
6. Validator: the rule-7 badge-host exemption of 6.2. No other rule changes; nothing reads
   `visible` (V10).
7. `add_legend` gains two optional row kinds: `("layer", <layer name>, text)` rendering a small
   swatch with the layer's name, and `("note", "", text)` for a plain line such as
   `Filtered: Application=payments (18 of 43 resources)`.

## 8. Layout changes (`scripts/oci_layout.py`)

Phase order, with the new phases in **bold** (everything else is v1.4.0's order, unchanged):

1. migrate legacy model -> **resolve the view (`_view_ctx` -> `oci_view.resolve_view`)** ->
   **filter and prune (`filter_model`, 6.5 / 6.6)** -> classify topology
2. title -> region -> compartment / tenancy containers -> VCN columns (subnets, items,
   `groups[]` boxes, badges - each gated by the resolved view) -> VCN-resident services ->

## 11. Migration and compatibility

- **One visible default change, reversible in one key (D1).** `label_mode` defaults to `network`.
  For a **hand-written** model nothing changes at all: V5 keeps the authored caption and the extra
  fields only appear when the item carries the matching metadata, which a hand-written model
  normally does not. For a **parser- or tenancy-produced** model, two things change: the compute /
  database **shape line disappears** from the caption (it moves to `metadata.shape`), and a
  **private IP and a port list appear** when the input carries them (plan / state JSON, or a live
  tenancy). `label_mode: "minimal"` gives the bare display name; the exact 1.4.0 caption for a
  parsed model is restored with `label_mode: "minimal"` plus `--label-fields display_name,shape`,
  which is documented in the CHANGELOG and in `gotchas.md` as the "1.4 caption" recipe.
- Everything else is off by default: `layers: "off"` (V3), `detail: "network"` = today's gates,
  `filter` empty, `mode: "all"`, `global_services: "osn"`, `show_edges: true`, no `purpose`. With
  those defaults a 1.4.0 model produces **byte-identical geometry**; only caption text can differ,
  and only for parsed models.
- **Schema**: still 2 (5). Schema-1 models keep going through `migrate_legacy_model`.
- **Cell ids**: unchanged for every existing element. New ids: `layer-<name>` for layers, `global`
  for the bucket, `global-compartments` for its text cell.
- **Validator**: one new exemption (6.2), which can only *remove* an error, and only for a badge
  with an `ociHost`. Files written by 1.2.0-1.4.0 validate exactly as before.
- **CLI**: every existing flag keeps its meaning, including `--vcn` and `--no-inferred-edges`
  (now an alias). New flags are listed in 6.2-6.9.
- **Generated scripts** that call `write_diagram(MODEL, path)` need no change.

## 13. Out of scope

Deferred with a stated reason:

- **AD / FD containers** (`--show-ad-fd`). No AD or FD container exists in the recipe; the `ha`
  purpose surfaces AD / FD as caption fields instead, which is the part that is readable at one
  glance. The containers are a v1.6.0 geometry change on the same footing as B03 was.
- **Multi-region canvases** and cross-region Remote Peering between two region boxes.
- **Security-rule reachability discovery.** The parser never reads security-list or NSG rule bodies
  (they are badge references), and a real computation needs route tables, security lists, NSGs and
  CIDR arithmetic evaluated together. The result would also be a dense graph that contradicts the
  0.3-0.6 edges per icon the workflow targets. Route-derived edges from a live tenancy
  (`ROUTES_TO`) are the supported subset, and they are now labelled `reachability` so the
  distinction is visible.
- **Observed-traffic discovery.** No telemetry source exists in the plugin; the enum value is
  reserved so a sidecar can carry it.
- **Tag-derived edges.** 6.8: tags are a filter and grouping dimension in this release.
- **Per-view page batches and per-view exports.** The guidelines' "separate views instead of one
  diagram" is partly answered by layers (one file, several readings) and partly by running the CLI
  twice; a `--views a,b,c` multi-page emitter is a v1.6.0 item once the presets have settled.
- **Separate text cells for IPs and ports.** They would be children of the same subnet as their
  icon, so they could not live on their own layer anyway (V2), and they would have to be kept clear
  of the caption box for rule 4. The field mechanism is strictly better.
- **A `metadata` schema.** `metadata` stays a free-form scalar map; only the keys 6.3 names are
  read.
- **Portrait canvas**, unchanged from the v1.4.0 deferral.

## 14. Decisions

Five choices were the author's rather than the specification's. All five were answered on
2026-09-19; the specification above is written to them, and they are not reopened in 1.5.0.

- **A1. The default of `mode` is per front end: `all` in `parse_terraform.py`, `participating` in
  `query_tenancy.py`.** A Terraform configuration is already a curated set - everything in it was
  written on purpose - so pruning it by default would silently drop items from small, deliberately
  written stacks. A tenancy dump is not curated, and it is the input that produces the unreadable
  diagrams the guidelines' "do not show every discovered OCI resource by default" is about. The
  command's Step 2 states which default is in force for the chosen input and how to switch
  (`--mode all` / `--mode participating`), and `layout_info["pruned"]` always reports what the mode
  removed. Affects 6.6 and 9.

- **A2. `global_services` defaults to `"osn"`; the Tenancy bucket is opt-in and switches on
  automatically under the `security` and `inventory` purposes.** Oracle's slides 29-31 draw IAM,
  Auditing and Policies inside the Oracle Services Network box; the guidelines' section 4 wants a
  separate global bucket (V7). Shipping the bucket as the default would move the OSN band's content
  in every existing diagram, and D1 already flips one default this release - two flips make the
  upgrade note harder to state than the feature is worth. The two purposes that are actually about
  tenancy-scoped objects turn it on without the reader having to know the key exists. Affects 6.7
  and 6.9.

- **A3. The reference sample migrates its authored IP addresses and shape text into `metadata` and
  is regenerated, together with `screenshots/` and `Screens/`.** The shipped canonical sample
  currently bakes those values into the caption strings, which means it bypasses exactly the
  renderer this release introduces (V5). Moving them into `metadata.private_ip` / `metadata.ports` /
  `metadata.shape` makes the sample exercise the renderer, and because `label_mode: "network"`
  re-renders the same lines, **the rendered text is identical** - the regeneration is a provenance
  change, not a visual one. The screenshot churn is one regeneration in a release that already
  changes parsed captions. Affects 10 and 11; the staleness gate
  (`test_committed_reference_diagram_is_not_stale`) is expected to fail until the sample is
  regenerated inside the task that changes it.

- **A4. `purpose` is persisted in `.claude/oci-drawio-architect.local.md`.** It is the one view
  choice that is remembered between runs, because the guidelines ask for the diagram's purpose to be
  recorded with the diagram. The rule from Step 0 stands unchanged: a view choice is never
  *detected* by `detect_settings.py`, only asked in Step 1 and then written back. The other view
  keys (`detail`, `label_mode`, `layers`, `filter`, `mode`, `global_services`) are not persisted -
  they are per-run choices, and a stale remembered filter is a silent correctness problem.
  Affects 6.9 and 10.

- **A5. `layers` defaults to `"off"` in 1.5.0** (V3), to be revisited in 1.6.0 once the layer set
  has been used in anger. Default-on would change the parent of every badge and every connector in
  every existing diagram, for a benefit that only appears when the reader opens the layers panel.
  With `"off"` the output is byte-identical to 1.4.0 for the same model apart from D1's caption
  change (11), which is the property the upgrade note needs. Affects 6.2 and 6.4.

## 15. Open questions

Neither question blocks implementation; both are recorded so the implementation task knows it owns
the first one.

1. **The OCI Search tag-predicate syntax** for server-side narrowing in `query_tenancy.py` (6.5).
   It must be verified against the OCI Search documentation during implementation; the design does
   not depend on it, because client-side filtering always runs.
2. **Whether `--label-fields` should accept a per-icon-kind mapping** (one field list for compute,
   another for databases). Not designed here; a single list plus `label_mode` covers every example
   in the guidelines, and a mapping can be added later as a superset without a schema change.
